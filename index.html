RotiOS

SaaS multitenant de gestión para rotiserías

Sistema de gestión de menú, pedidos y caja donde una sola base de datos y un solo deploy atienden a varios locales, cada uno completamente aislado de los demás.

Proyecto individual, desarrollado al 100 % por Ezequiel.

› Problema que resuelve

Una rotisería toma pedidos por teléfono y por mostrador, los anota en papel o los recuerda de memoria, y al cerrar el día no sabe si la plata del cajón se corresponde con lo que vendió. Con delivery, nadie sabe con certeza qué pedidos están en la calle ni cuáles ya se cobraron.

Qué resuelve concretamente
  • El pedido queda registrado con el precio del momento, así los cierres de caja viejos siguen siendo correctos aunque cambien los precios.
  • El estado del pedido es visible (preparando, listo, en camino, entregado), tanto para el mostrador como para el repartidor.
  • La caja cuadra, o se sabe por cuánto no cuadra: el cierre compara el efectivo contado contra el esperado y guarda la diferencia.
› Funcionalidades
  • Menú con categorías, productos y variantes (por ejemplo cuarto, medio y entero).
  • Pedidos de retiro y delivery, con costo de envío configurable.
  • Caja: apertura de turno, cobros en cuatro medios de pago (efectivo, transferencia, débito y crédito), movimientos de ingreso y egreso, y cierre con arqueo.
  • Cuatro roles: superadmin (alta de locales), admin (dueño del local), cajero y repartidor.
  • Vista propia para el repartidor: solo ve los pedidos que lleva y los marca como entregados.
› Decisiones técnicas destacadas
  1. Aislamiento entre locales (multitenancy) a nivel de acceso a datos. Una sola base con una columna tenantId, pero el filtro no se escribe a mano: se inyecta con un contexto por request (AsyncLocalStorage) y una extensión de Prisma. Si falta el contexto, el sistema lanza un error en lugar de consultar sin filtro.
  2. El tenantId sale solo del token JWT. Ningún endpoint de dominio lo acepta por body, query ni header.
  3. Pedir un recurso de otro local devuelve 404, nunca 403, para no confirmar que ese id existe.
  4. El repartidor tiene endpoints propios en lugar de permisos sobre los del mostrador: el alcance del rol queda escrito en el router y en la validación.
  5. Arquitectura en capas (routes, controllers, services, repositories) con interfaces explícitas e inyección de dependencias por constructor.
  6. Borrado lógico en el menú, porque los pedidos históricos tienen que seguir siendo legibles.

docker compose up -d                 # PostgreSQL en localhost:5433

cd Backend
cp .env.example .env
npm install

npm run seed                         # 3 rotiserías demo con un día de operación

# en otra terminal

npm install

Folderly

Ordena la carpeta Descargas de una vez, con un botón

Aplicación de escritorio para Windows que agarra los archivos sueltos de una carpeta y los acomoda en subcarpetas según su tipo, con un botón para deshacer el último orden. Se distribuye como un único .exe, sin instalación.

Proyecto individual, desarrollado al 100 % por Ezequiel.

› Capturas de pantalla
› Proceso que automatiza

Ordenar a mano una carpeta Descargas desordenada: crear carpetas, mirar la extensión de cada archivo, arrastrarlos y resolver duplicados. Lleva entre 15 y 40 minutos cada vez; Folderly lo hace en segundos.

Cómo se usa
  1. Doble clic en Folderly.exe.
  2. Viene elegida la carpeta Descargas (se puede cambiar).
  3. Botón Ordenar ahora y confirmación.
  4. Se ve el progreso archivo por archivo; la ventana no se congela.
  5. Si no gusta el resultado, Deshacer último orden devuelve todo a su lugar.

Categorías: Imágenes, Documentos, Planillas, Videos, Música, Instaladores, Comprimidos y Otros (8 en total).

› Garantías de seguridad

Lo que nunca hace.

  • No pisa archivos: si ya existe foto.jpg, el nuevo queda como foto (1).jpg.
  • No toca subcarpetas ni archivos ocultos ni descargas en curso.
  • No se mueve a sí misma.
  • No se cierra si un archivo está en uso: lo saltea y avisa al final.
› Decisiones técnicas destacadas
  1. Interfaz que no se congela: el trabajo corre en un hilo aparte y se comunica con la ventana por una cola, porque tocar la interfaz desde otro hilo rompe Tkinter.
  2. Lógica pura separada de la interfaz, para poder probarla sin abrir ninguna ventana.
  3. Casos reales de Windows resueltos: la carpeta Descargas se busca en el registro (puede estar en otro disco) y las carpetas vacías de solo lectura que deja OneDrive se pueden borrar.
  4. Cero dependencias externas: todo viene con Python; el .exe pesa unos 11 MB.
